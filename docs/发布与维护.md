# 发布与维护

## 页面结构

当前原型集中在 `apps/storefront/index.html`，HTML、样式和交互脚本内联。这样保留了已确认版本的行为；后续拆分 CSS/JavaScript 时，应分阶段迁移并核对语言切换、二级菜单、移动导航、购物车、结算演示及会员快捷支付等交互。

## 发布方式

工作流 `.github/workflows/pages.yml` 在 `main` 分支发生推送时，将 `apps/storefront` 目录发布到 GitHub Pages。仓库 Pages 使用 GitHub Actions 构建与部署。

## 日常步骤

1. 只修改与原型相关的文件，不把其他项目副本拼接进来。
2. 在浏览器检查桌面和窄屏布局、语言切换及主要演示交互。
3. 确认变更不含凭据、真实用户/交易数据或生产环境配置。
4. 提交并推送到 `main`；在 GitHub Actions 检查 `Deploy GitHub Pages` 工作流完成，再打开 README 中的预览链接。

## 生产环境

Pages 是公开的静态测试地址，不应用于真实交易。正式服务需独立设计与建设，不能通过把密钥写入静态页面来接入生产支付。
